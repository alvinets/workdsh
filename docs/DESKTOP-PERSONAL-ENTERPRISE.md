# Desktop 个人与企业使用

WorkDSH Desktop 的个人与企业模式使用同一套官方 DSH 核心、完整客户端和共同功能插件。企业模式增加公司账号与后台连接，本机对话、文件和工具仍由官方 DSH 执行。企业 Web 保持服务器运行方式。

| 使用方式 | 对话与工具的执行位置 | 公司后台的作用 |
| --- | --- | --- |
| 个人 Desktop | 用户电脑 | 无需企业登录或公司服务 |
| 企业 Desktop | 员工电脑 | 登录、组织、权限、模型转发与授权正文接收 |
| 企业 Web | ECS 上按账号运行的官方 DSH 进程 | 登录、组织、权限、模型转发与审计 |

模型推理在供应商或自部署模型服务执行；远程 MCP 在其所在服务执行。“Desktop 本机执行”指本机官方 DSH、工作区与本地工具，不代表所有调用都离线。

## 个人使用

在入口选择个人模式即可进入个人空间。官方设置、模型配置、插件管理和右侧面板均来自官方客户端。

默认自有功能包括专家、技能、资料库和 MCP/连接器，以及运行必需的基础依赖。这不等于预装全部专家定义、技能或 MCP 服务。用户可以按需安装其他插件，在官方模型设置中配置自己的模型。

## 企业管理员准备

管理员先部署企业后台，并为员工提供按公司地址打包的 Desktop。打包时通过 `WORKDSH_DEPLOYMENT_CONFIG` 指定 JSON 文件，例如：

```json
{
  "enterprise": {
    "backendUrl": "https://workdsh.company.com"
  }
}
```

后台地址写入应用资源中的 `workdsh-config.json`。公司包使用该固定地址，员工无法通过入口表单、已保存地址或页面参数改为其他后台。配置文件只接受后台地址，不接受账号、密码、服务器管理密钥或模型 Key。通用个人包使用空配置 `{}`。

企业后台须提供有效 HTTPS 地址并通过正常证书验证；HTTP 仅允许本机回环开发地址。管理员在后台配置真实模型 API 和供应商 Key，并向成员提供内部模型地址、内部访问 Key、协议与允许使用的模型。

## 企业用户使用

1. 在入口选择企业模式，使用公司提供的账号登录固定后台。
2. 登录成功后进入本机官方客户端。企业账号插件已随包提供，仅企业模式启用，无需选择或安装 tgz 文件。
3. 在设置的“企业账号”页查看姓名、邮箱、组织名称、角色与正文同步状态，并可退出企业账号。
4. 在官方“模型 → 自定义模型 API”中填写公司内部地址、内部 Key、协议和模型；也可以保留自己的模型配置。Desktop 不自动注入企业模型或覆盖用户配置。
5. 正常创建对话，文件处理和本地工具在当前企业账号的本机工作区执行。

企业账号与个人空间分开。企业空间按后台来源、组织和成员划分，分别保存 Home、Profile、凭据、工作目录、会话和窗口存储。重新登录原账号恢复原空间；切换到个人模式使用个人空间。目录分离是数据归属边界，不能代替操作系统安全沙箱。

企业账号插件由安装包供应，随 Desktop 版本更新；个人默认组合不启用它。协作、通知和其他业务应用仍是按需安装的独立插件。

## 正文同步与退出

本机会话仍由官方 DSH 保存。企业账号插件向后台同步已提交的用户和助手可见正文，并显示同步状态；失败时保留重试状态。思考、工具轨迹、文件和凭据不在正文同步范围内，文件分享需要相应功能与明确操作。后台验证实际成员身份，管理员只能只读查看本组织授权正文，查看行为记录审计。

退出企业账号时，Desktop 停止对应本机 DSH 和工具进程，取消企业操作，清除本机认证与窗口登录状态，并请求后台撤销登录；该账号业务数据保留。后台撤销失败会明确提示远端撤销未确认，本机仍退出，不转为个人身份继续运行。共享内部模型 Key 的撤销由网关凭据规则管理，企业账号退出不自动撤销所有模型 Key。

正文同步依赖客户端提交，不构成不可绕过的完整终端审计。后台不可达时无法完成新登录，企业操作及同步需按各自授权规则处理。

## 运行与发行边界

Electron 负责入口、登录、本机进程和窗口；官方 Host、设置、侧栏、右侧面板与 Agent 流程来自同一官方运行包。登录 bearer 只由 Main 持有；业务窗口不获得 carrier preload、Node integration 或后台登录凭据。企业插件通过受控本机接口读取账号、退出与同步正文，该接口不提供任意 URL 代理。

每个个人或成员 Profile 保存自己的插件选择、配置和锁文件。安装包供应共同只读依赖；独立安装的插件写入当前可写 Profile。重启及基础版本升级保留用户配置与插件选择，不经共享依赖链接改写安装包。无法确认所有权的旧 Profile 不自动改写，保留数据并显示错误。

产品目标版本与用户已安装应用的实际版本须分别核对；更新源码 pin 不等于已安装应用升级。不同平台的安装、图形窗口、本机工具和退出行为需要分别验收，不能以一个平台或源码检查代替所有平台支持。开发候选包与正式签名、发布安装包的状态应在发行说明中区分。

源码责任、运行时组合与打包校验要求见[Desktop 所有权边界](desktop-boundaries.md)。
